# Task 24 — Quad-SPI (QSPI) & Dual/Octal-SPI Multi-Lane Flash & PSRAM Hardware Host Controller

## 1. Overview & Motivation

High-speed external non-volatile Flash memory (NOR Flash) and pseudo-static RAM (PSRAM) are ubiquitous across modern embedded and SoC platforms:
1. **Quad-SPI (QSPI)**: The industry standard 4-lane interface (IO0..IO3) supported by Winbond (W25Q series), Macronix (MX25), Micron, ISSI, and APMemory (APS6404 QSPI PSRAM). Quad-SPI achieves up to a **4x throughput enhancement** over traditional single-lane SPI without requiring parallel bus pin counts.
2. **Dual-SPI & Octal-SPI (xSPI / OSPI)**:
   - Dual-SPI (2-lane IO0/IO1) provides double throughput for cost-sensitive 2-wire designs.
   - Octal-SPI (8-lane IO0..IO7) utilizes all 8 physical GPIO pins of the emulator for maximum data bandwidth (supporting ultra-fast XIP code execution and high-speed data acquisition).
3. **Autonomous Multi-Phase Protocol Engine**: Standard SPI Flash operations (such as Winbond `0xEB` Fast Read Quad I/O) consist of distinct protocol phases:
   - **Instruction Phase**: 8-bit command byte sent on single or multi-lane.
   - **Address Phase**: 24-bit (3-byte) or 32-bit (4-byte) physical address serialized across configured lanes.
   - **Dummy Clock Phase**: 0..15 dummy wait cycles with IO pins in high-impedance (Hi-Z) allowing flash internal memory sensing.
   - **Data Phase**: Continuous multi-byte burst read (`IN QSPI`) or write (`OUT QSPI`) with automatic SCK toggling.

**Task 24 integrates a Dedicated Hardware Multi-Lane SPI Host Controller directly into the OmniBus Protocol Emulator ASIC core**, enabling autonomous Quad-SPI, Dual-SPI, and Octal-SPI memory communication with zero CPU bit-banging overhead.

## 2. Hardware Architecture & Pin Mapping

```
                               +--------------------------------------------------------------+
                               |        OmniBus Multi-Lane SPI Hardware Host Controller       |
                               |                                                              |
    Microcode / Wishbone ------> [ Protocol Phase Sequencer ]                                 |
                               |   ├── State 1: CMD (8-bit command serialization)             |
                               |   ├── State 2: ADDR (24b / 32b multi-lane address shift)     |
                               |   ├── State 3: DUMMY (0..15 clock cycles with Hi-Z bus)      |
                               |   ├── State 4: DATA_RX (Multi-lane nibble/pair/octal read)   |
                               |   └── State 5: DATA_TX (Multi-lane nibble/pair/octal write)  |
                               |                                                              |
                               | [ Multi-Lane Bus Multiplexer & OE Control ]                  |
                               |   ├── Lane 0 (IO0 / MOSI): Pin 0                             |
                               |   ├── Lane 1 (IO1 / MISO): Pin 3 (auto-routed default)       |
                               |   ├── Lane 2 (IO2 / WP#) : Pin 4                             |
                               |   ├── Lane 3 (IO3 / HOLD#): Pin 5                            |
                               |   └── Lanes 4..7: Pins 4..7 (Octal mode across all 8 pins)   |
                               +--------------------------------------------------------------+
                                      |            |            |             |
                                      v            v            v             v
                                 IO0 (Pin 0)  IO1 (Pin 3)  IO2 (Pin 4)   IO3 (Pin 5)
                                 SCK (Pin 1)  CS# (Pin 2)  [Mirrored on o_spi_sck/cs_n]
```

### A. Pin Routing Table
| Protocol Signal | GPIO Pin | Direction | Description |
| :--- | :--- | :--- | :--- |
| **SCK** | Pin 1 (`sck_pin`) | Output | Serial clock generated by host sequencer (mirrored to `o_spi_sck`) |
| **CS#** | Pin 2 (`cs_pin`) | Output | Direct chip-select control (mirrored to `o_spi_cs_n`) |
| **IO0 (MOSI / SI)** | Pin 0 (`tx_pin`) | Bidirectional | Lane 0: Command out, Address out, Data I/O |
| **IO1 (MISO / SO)** | Pin 3 (`rx_pin`) | Bidirectional | Lane 1: Input in Single mode; Data I/O in Dual/Quad/Octal mode |
| **IO2 (WP#)** | Pin 4 | Bidirectional | Lane 2: Quad/Octal Data I/O (Write Protect disabled during Quad) |
| **IO3 (HOLD#)** | Pin 5 | Bidirectional | Lane 3: Quad/Octal Data I/O (Hold disabled during Quad) |
| **IO4..IO7** | Pins 4..7 / 0..7 | Bidirectional | Lanes 4..7: Octal 8-bit parallel transfers |

### B. Dedicated Registers & Signals
| Register / Signal | Width | Reset | Description |
| :--- | :--- | :--- | :--- |
| `qspi_en` | 1 bit | `1'b0` | Master enable for QSPI multi-lane host engine |
| `qspi_width` | 2 bits | `2'b00` | Bus width: `00`=Single (1b), `01`=Dual (2b), `10`=Quad (4b), `11`=Octal (8b) |
| `qspi_cpol` | 1 bit | `1'b0` | Clock polarity: `0`=idle Low (Mode 0), `1`=idle High (Mode 3) |
| `qspi_state` | 4 bits | `4'd0` | Sequencer state (0=IDLE, 1=CMD, 2=ADDR, 3=DUMMY, 4=DATA_RX, 5=DATA_TX) |
| `qspi_cmd_byte` | 8 bits | `8'd0` | 8-bit command register for autonomous serialization |
| `qspi_addr_reg` | 32 bits | `32'd0` | 32-bit physical address storage register |
| `qspi_addr_bits`| 6 bits | `6'd0` | Remaining address bits to serialize (24 or 32) |
| `qspi_dummy_cnt`| 4 bits | `4'd0` | Remaining dummy wait cycles counter (0..15) |
| `qspi_rx_byte` | 8 bits | `8'd0` | Deserialized byte received across multi-lane bus |
| `qspi_oe` | 1 bit | `1'b0` | Output enable for multi-lane data bus (0=Hi-Z input, 1=Host drive) |

## 3. Microcode Instruction Set Extensions

### A. QSPI Instructions
| Mnemonic | Opcode | Description |
| :--- | :--- | :--- |
| `QSPI_CFG <en>, <width>, <cpol>` | `0xF5B0`..`0xF5BF` | Configure QSPI host controller mode (`width`: 1=Single, 2=Dual, 4=Quad, 8=Octal) |
| `QSPI_CS <0\|1>` | `0xF5C0` / `0xF5C1` | Direct chip-select assertion (`0`=active Low, `1`=idle High) |
| `QSPI_CMD` | `0xF5D0` | Autonomously transmits 8-bit command in `acc` on Lane 0 (MOSI) |
| `QSPI_LOAD_ADDR <0..3>` | `0xF5F0`..`0xF5F3` | Loads `acc` into address byte index 0 (MSB) to 3 (LSB) |
| `QSPI_ADDR <24\|32>` | `0xF5F8` / `0xF5F9` | Autonomously shifts 24-bit or 32-bit address across configured lanes |
| `QSPI_DUMMY <0..15>` | `0xF5E0`..`0xF5EF` | Clocks $N$ dummy wait cycles with pins in high-impedance (Hi-Z) |
| `IN QSPI` | `0x2F00` | Autonomously receives 1 byte across multi-lanes into `isr`, `acc`, and `o_data` |
| `OUT QSPI` | `0x1F00` | Autonomously transmits 1 byte from `osr` across multi-lanes |

### B. Microcode Sequence Example (Winbond W25Q128 Quad Fast Read 0xEB)
```asm
    ; 1. Enable QSPI in Quad mode (4 lanes)
    QSPI_CFG MODE=QUAD, CPOL=0

    ; 2. Assert Chip Select (CS# low)
    QSPI_CS 0

    ; 3. Send Command 0xEB on MOSI
    MOV acc, 0xEB
    QSPI_CMD

    ; 4. Send 24-bit physical address 0x102030 across 4 lanes (6 clock cycles)
    MOV acc, 0x10
    QSPI_LOAD_ADDR 0
    MOV acc, 0x20
    QSPI_LOAD_ADDR 1
    MOV acc, 0x30
    QSPI_LOAD_ADDR 2
    QSPI_ADDR 24

    ; 5. Clock 6 dummy wait cycles (Hi-Z)
    QSPI_DUMMY 6

    ; 6. Read 4 payload data bytes at maximum throughput
    IN QSPI
    PUSH
    IN QSPI
    PUSH
    IN QSPI
    PUSH
    IN QSPI
    PUSH

    ; 7. Deassert Chip Select (CS# high)
    QSPI_CS 1
halt:
    JMP halt
```

## 4. Wishbone Peripheral Integration (`ADDR_QSPI = 8'h20`)

The memory-mapped register at `ADDR_QSPI` provides full hardware telemetry and state inspection for the host CPU:

| Bit Range | Field Name | Access | Description |
| :--- | :--- | :--- | :--- |
| `[31:16]` | `qspi_addr_reg[15:0]` | RO | Lower 16 bits of current physical address register |
| `[15:8]` | `qspi_rx_byte[7:0]` | RO | Last byte received across multi-lane bus |
| `[7:4]` | `qspi_state[3:0]` | RO | Current FSM state (`1`=CMD, `2`=ADDR, `3`=DUMMY, `4`=RX, `5`=TX) |
| `[3]` | `qspi_cpol` | RO | Clock polarity configuration |
| `[2:1]` | `qspi_width[1:0]` | RO | Configured bus width (`00`=Single, `01`=Dual, `10`=Quad, `11`=Octal) |
| `[0]` | `qspi_en` | RO | Master QSPI host engine enable flag |

## 5. Verification & Test Suite

All 4 dedicated Task 24 tests were implemented in `test_rtl/simulation/cocotb/ProtocolEmulator/testbench.py` and simulated with Icarus Verilog and Cocotb:

1. **`test_qspi_quad_fast_read_w25q`**:
   - Simulates Winbond W25Q128 Quad Fast Read (CMD `0xEB` 1-4-4 mode).
   - Microcode loads 24-bit address `0x102030`, executes 6 dummy clocks, and receives 4 consecutive bytes (`[0xDE, 0xAD, 0xBE, 0xEF]`).
   - Verified exact data deserialization and FIFO push.
   - **Result: PASS**.

2. **`test_qspi_dual_read`**:
   - Simulates Dual SPI Read (CMD `0x3B` 1-2-2 mode).
   - Microcode loads 24-bit address `0x010203`, executes 4 dummy clocks, and receives 2 bytes (`[0xA5, 0x5A]`).
   - Verified exact 2-bit dual-lane reception across IO0 and IO1.
   - **Result: PASS**.

3. **`test_qspi_quad_write_stream`**:
   - Verifies `OUT QSPI` burst transmission across 4 parallel lanes.
   - Microcode writes 3 consecutive payload bytes (`[0x12, 0x34, 0x56]`).
   - Captured and verified all 4-bit nibbles on IO0..IO3 with precise SCK clock synchronization.
   - **Result: PASS**.

4. **`test_qspi_octal_transfer`**:
   - Verifies Octal-SPI 8-lane parallel transfer.
   - Transmits `0x55` out across all 8 GPIO pins and receives `0xAA` in a single clock cycle.
   - **Result: PASS**.
